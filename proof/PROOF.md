# Доказательство работы страницы `/companies` (задача 2)

Страница поднята локально (`npm run dev`, `http://localhost:3000/companies`) поверх той же базы PostgreSQL из задачи 1 (1190 компаний после мёржа review.csv). Данные тянутся **серверно** — Server Component делает параметризованные SQL-запросы к Postgres, в браузер уходит уже готовый HTML.

## Как проверял сам
1. **Пустой запрос** — открыл `/companies` без параметров: таблица отдаёт 1190 записей (счётчик «Найдено: 1190», показаны первые 200), колонки Название/Категория/Город/Адрес/Рейтинг/Отзывов/Сайт/Телефон. Отсортировано по `reviews_count DESC` — сверху компании с самым большим числом отзывов, это сразу видно глазами.
2. **Поиск по названию** — вбил `Медиа`: в выдаче остались только компании, где `Медиа` в названии (`ILIKE '%Медиа%'`, регистронезависимо). Проверил, что счётчик уменьшился и в таблице нет посторонних.
3. **Фильтр по городу** — выбрал `Москва` в выпадашке: остались только московские компании. Список городов в выпадашке подтягивается из БД (`SELECT DISTINCT city`), а не захардкожен.
4. **Комбинация** — `Сфера` + `Казань` одновременно: 3 записи, оба условия склеены через `AND`. Появились бейджи «название: Сфера» и «город: Казань» и кнопка «Сбросить» → возвращает на чистый `/companies`.
5. **Пустая выдача** — специально задал заведомо несуществующее название: вместо пустой таблицы показывается аккуратный блок «Ничего не найдено».
6. **Параметры в URL** — форма отправляется через `GET`, так что состояние поиска/фильтра лежит в query-строке (`?q=…&city=…`) и ссылку можно расшарить/обновить страницу без потери фильтра.

## Что ломалось в процессе (честно)
- **Встроенный браузер не видел `localhost`** — он работает в отдельном сетевом контексте, навигация на `localhost:3000` и на LAN-IP отклонялась. Скриншоты в итоге снял через **headless Microsoft Edge** (`msedge.exe --headless=new --screenshot`), который живёт в той же сети, что и dev-сервер.
- **`searchParams` в Next.js 15 стал асинхронным** — сначала читал его как объект и получал предупреждение; поправил на `await searchParams` (в 15-й версии это Promise).
- **Предупреждение про два `package-lock.json`** (корень репо + `web/`) — Next выбирал workspace root эвристикой; зафиксировал явно через `outputFileTracingRoot` в `next.config.mjs`.
- **NUMERIC из pg приходит строкой** — `rating` рендерил как есть; учёл, что тип в TypeScript — `string | null`, а не `number`.

## Безопасность
- Никаких секретов в репозитории: строка подключения только в `web/.env` (в `.gitignore`), в репо лежит `web/.env.example`.
- Все SQL-запросы параметризованы (`$1, $2, …`) — защита от инъекций в поле поиска.
