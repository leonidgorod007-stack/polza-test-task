# ANOMALIES.md — что не так с `review.csv`

`review.csv` подавался как «свежая выгрузка для той же базы». По факту это **грязный дамп с подмешанными старыми записями и множеством битых значений**. Ниже — всё странное, что нашлось, и **как именно** это обнаружено.

**Как проверял (метод):**
1. Распарсил CSV собственным парсером (RFC 4180, с учётом кавычек) — `scripts/csv.mjs`.
2. Загрузил сырьё «как есть» в staging-таблицу `reviews_raw` (все колонки `TEXT`), чтобы битые значения не рушили импорт.
3. Прогнал валидацию каждого поля регулярками/парсерами и сверил `id` с уже загруженной базой из задачи 1 (`scripts/load_reviews.mjs`).
4. Отдельно проверил сырые байты файла (`cat -A`) — переносы строк и пустые строки.

Итого строк данных: **207** (207 непустых записей CSV после заголовка).

---

## 1. Главный «сюрприз»: под видом свежих данных — старые записи
6 строк ссылаются на `id`, которые **уже есть** в базе из задачи 1 (диапазон `c_000xxx`), а не на новый диапазон `c_001xxx`:

`c_000098, c_000246, c_000263, c_000425, c_000769, c_000851`

Поля в них совпадают с уже загруженными компаниями — то есть это **не обновления, а дубли ранее выгруженного**. «Свежей» выгрузка не является.
**Как нашёл:** пересечение множества `id` из CSV с `SELECT id FROM companies`.
**Что сделал:** при мёрже эти строки пропущены (`ON CONFLICT DO NOTHING` + явная проверка), чтобы не плодить дубли.

## 2. Две полностью пустые строки
В конце файла две строки вида `,,,,,,,,` (только запятые, все поля пустые), строки 207–208.
**Как нашёл:** `tail -4 review.csv | cat -A` показал `,,,,,,,,^M$`; в коде — строки, где все поля пустые.
**Что сделал:** отброшены как мусор.

## 3. Дубликаты `id` внутри самого файла
Три `id` встречаются дважды (записи идентичны): `c_001049`, `c_001050`, `c_001075`.
**Как нашёл:** подсчёт частот `id` среди непустых строк.
**Что сделал:** в базу берётся один экземпляр (дедупликация по `id`).

## 4. Битые значения `rating`
| id | значение | проблема |
|----|----------|----------|
| `c_001083` | `N/A` | не число |
| `c_001122` | `-3` | отрицательный, вне диапазона 0–5 |
| `c_001186` | `7.2` | больше 5, вне диапазона |
| `c_001010` | `4,5` | десятичный разделитель — запятая вместо точки |

`4,5` — валидное значение (4.5), просто в «европейском» формате: при загрузке нормализуется (`,`→`.`). Остальные три — реально невалидны и записаны как `NULL`.
Плюс ~20 строк с пустым `rating` (допустимо — как и `NULL` в исходной выгрузке).
**Как нашёл:** `parseRating()` — регулярка на число + проверка диапазона 0–5.

## 5. Битые значения `reviews_count`
| id | значение | проблема |
|----|----------|----------|
| `c_001116` | `-10` | отрицательное число отзывов |
| `c_001079` | `45.5` | дробное, а должно быть целое |
| `c_001187` | `много` | текст вместо числа |

**Как нашёл:** `parseReviews()` — только целое ≥ 0 считается валидным.
**Что сделал:** невалидные → `0` (поле в схеме `NOT NULL DEFAULT 0 CHECK >= 0`).

## 6. Битые значения `site`
| id | значение | проблема |
|----|----------|----------|
| `c_001132` | `https://` | схема без домена |
| `c_001064` | `нет сайта` | текст-заглушка вместо URL |
| `c_001020` | `htp://sintez-service-453.ru` | опечатка в схеме (`htp` вместо `http`) |

Плюс ~60 строк с пустым `site`.
**Как нашёл:** проверка URL регуляркой `^https?://…\.…$`.
**Что сделал:** невалидные → `NULL`.

## 7. Битые значения `phone`
| id | значение | проблема |
|----|----------|----------|
| `c_001004` | `8 (925) abc-12-34` | буквы вместо цифр, префикс `8` вместо `+7` |
| `c_001091` | `+7` | обрезанный номер |

Плюс ~22 строки с пустым `phone`.
**Как нашёл:** маска `^\+7 \(\d{3}\) \d{3}-\d{2}-\d{2}$`.
**Что сделал:** невалидные → `NULL`.

## 8. Лишние пробелы
`c_001184` — город `"Москва "` с хвостовым пробелом (без чистки попал бы отдельным городом от `Москва`).
**Как нашёл:** сравнение `value !== value.trim()`.
**Что сделал:** `TRIM` при загрузке.

## Прочее наблюдение (не по данным, а по ТЗ)
В критериях оценивания упомянут пункт «реальные, валидные **email**», но **в датасете колонки `email` нет вовсе** — есть только `site` и `phone`. Похоже, критерий частично унаследован от другой версии задания. Ближайшие контактные поля (`site`, `phone`) я провалидировал (см. пункты 6–7).
